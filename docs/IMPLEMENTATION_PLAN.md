## Порядок работ

| Этап | Результат | Условие перехода |
| --- | --- | --- |
| 0. Решения | Универсальная активация на сайтах, включая YouTube; без автопаузы; бесплатный API | Получены; кандидат MyMemory прошел один запрос без ключа |
| 1. Проверка реализуемости | Универсальное DOM-наведение без переписывания субтитров, TextTrack-слой, ручная область, доступные iframe; прототип на fixtures | Слово определяется без адаптера домена; видео продолжает играть |
| 2. Контракты и каркас | Manifest, сборка, shared-типы, сообщения, тестовый плеер, интерфейсы адаптеров/провайдера, ADR по переводу | Каркас загружается в Firefox, API выбран и доступен для проверки |
| 3. Функциональность | UI, общий DOM/TextTrack-механизм, hover без паузы, реальный бесплатный перевод, кэш, настройки и разрешения | Основной сценарий проходит целиком, активация нового домена не требует изменения кода |
| 4. Надежность | YouTube: обычные/автоматические субтитры; iframe, ошибки, гонки запросов, SPA, fullscreen, очистка ресурсов, безопасность | Все P0 и обязательные проверки выполнены; dom-drakona.online — при появлении доступа |
| 5. Личная приемка | Тестовый пакет, инструкция установки, отчет с задержками/качеством/ограничениями | Пользователь посмотрел серию и подтвердил удобство |
| 6. Расширение продукта | Дополнительные сайты, фразы, словарь, импорт субтитров; затем публикация | Отдельный согласованный объем |

Если конкретный сайт не предоставляет доступный текст, общий механизм продолжает работать на других сайтах. Для исключения записываются причина и варианты: ручная область, дополнительный адаптер, импорт субтитров или отдельное исследование OCR. OCR остается вне MVP; отсутствие адаптера само по себе не означает несовместимость.

Диагностическая карточка этапа 1 нужна только для проверки наведения и не выдается за настоящий перевод. Конечный MVP обязательно проверяется с реальным сервисом.

Сроки оценивать после этапа 1: надежность определения текста в разных плеерах и ограничения API пока неизвестны. Единица планирования — проверяемый результат этапа, а не количество агентов.

## Агенты

Предлагаются роли задач для универсальных coding-агентов; устанавливать специальные агенты NestJS/CRM не требуется. Это распределение для последующего параллельного развития; первая сборка выполнена ведущим.

| Агент | Ответственность и владение файлами | Результат |
| --- | --- | --- |
| Ведущий / архитектор — основной агент | `manifest`, package/build config, `src/shared/**`, контракты, ADR, интеграция | Firefox-архитектура, минимальные разрешения, согласованные интерфейсы, сборка |
| Агент плееров и субтитров | `src/adapters/**`, `src/content/detection/**`, fixture-плееры | Универсальный DOM hit-test, TextTrack, iframe, область субтитров, cleanup; без управления воспроизведением |
| Агент интерфейса расширения | `src/content/ui/**`, `src/content/hover/**`, `src/popup/**`, `src/options/**` | Интерактивные слова, карточка, настройки, состояния ошибок и fullscreen-позиционирование |
| Агент перевода | `src/background/**`, `src/providers/**`, собственные тесты | Бесплатный API без ключа, очередь, кэш, отмена/актуальность, обработка квоты и ошибок |
| Агент QA и ревью | `tests/integration/**`, `tests/browser/**`, `docs/QA_REPORT.md`; обзор остальных файлов без параллельных правок | Проверка сценариев PRD в Firefox, регрессий, разрешений и отсутствия утечек |

Все исполнители знают, что работают в общей кодовой базе: не отменяют чужие изменения, не редактируют файлы другого владельца без координации, сообщают о требуемых изменениях контрактов ведущему. Тесты собственных модулей пишет их владелец. QA дополняет независимыми сценариями, а не заменяет эти тесты.

## Параллельность и зависимости

Доступно до четырех одновременно активных агентов вместе с ведущим. Все пять ролей одновременно не запускаются.

1. Прототип и shared-контракты: ведущий, при необходимости агент плееров.
2. После стабилизации контрактов: ведущий + плееры + UI + перевод параллельно, с разделением файлов.
3. Когда освобождается слот: QA; ведущий интегрирует, владельцы последовательно исправляют найденные дефекты.
4. Общая приемка и упаковка выполняются после интеграции, а не по отдельным заявлениям агентов об успехе.

## Контракты до разделения задач

- `SubtitleCue`: id сессии и реплики, текст, язык, известные времена начала/конца.
- `PlayerAdapter`: detect, subscribe, getContainer, getVideo, capabilities, dispose.
- `HoverTarget`: реплика, границы выбранного слова, текст, геометрия.
- `TranslationRequest`: requestId, слово, source/target, опциональный контекст, версия настроек.
- `TranslationResult`: requestId, перевод, режим контекста, источник кэш/сеть; типизированная ошибка отдельно.
- `Settings`: включенные сайты, языки, задержки, бесплатный провайдер и разрешение передачи выбранного слова. Ключ, настройка автопаузы и PlaybackController отсутствуют.
